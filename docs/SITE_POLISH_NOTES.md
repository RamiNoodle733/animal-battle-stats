# Site polish and growth priorities

The community owner tools now open in a full-width Events workspace. Filters collapse, recent-period shortcuts preserve account exclusions, and failed pagination preserves already loaded events. Overview remains available on laptops. Phone rows wrap their metadata, and both layout modes use readable text surfaces.

Animal vote totals show both sides in the animal database and fan lists; the net score remains a secondary sorting measure. Profile selection validates against the current versioned catalogue, rather than the legacy database roster. New accounts get a free random profile animal excluding pig/boar relatives. The owner can backfill missing avatars from Community → World stats → Events → Settings; existing choices are preserved and repeating the assignment does not replace them. This assigns profile avatars, not paid packs or collection cards.

The 4.15 pass fixes missing IDs on 119 added animals, opens community discussions in shareable threads, restores anonymous composing, and connects profile pictures to collected cards. Existing profile animals receive a welcome card when their account returns; later profile selections require an owned card. The random welcome gift is free and does not consume the three-card starter choice. Owner Events now includes account/guest and account/country/state/city selectors with dependent location choices and expanded CSV columns.

Prioritize these next experiments, checking results before expanding them:

1. **Search landing pages:** improve the Compare and Tier List entry flows first. Create a small set of carefully sourced matchup explainers and link them from relevant animal profiles. Clear answers, assumptions, and source links should come before generating more pages. Track organic engaged sessions and fight starts, not just impressions. [Google's people-first guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) and [crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable).
2. **A reason to return:** test a weekly matchup challenge using the existing Vote challenge-sharing flow. Prepare short real-animal clips or cards around the same matchup, with a distinct tagged link per channel. Measure completed challenges and returning players. Publishing posts requires a separate request; no campaign was posted during this pass.
3. **Roblox attribution:** create distinct Roblox share links for the website, YouTube, Discord, and other channels, then compare qualified plays and retention. Website play clicks measure intent, not verified joins. [Roblox share links](https://create.roblox.com/docs/production/promotion/share-links) and [acquisition](https://create.roblox.com/docs/production/analytics/acquisition).
4. **Account activation:** finish Google, GitHub, Roblox, and email-provider setup before promoting those sign-in methods. See `ACCOUNT_PROVIDER_SETUP.md`. Monitor successful signup followed by a first meaningful action; new measurement goals need time to accumulate data.

Treat traffic spikes as an investigation prompt. Compare engagement, pages per session, sources, and repeated-request patterns before calling traffic automated or buying ads. Keep account activity stored and use view filters for owner/test activity. Analytics providers use different definitions and GA session counts can be approximate; do not equate an internal visitor pseudonym with a GA active user. [GA reporting expectations](https://developers.google.com/analytics/devguides/reporting/data/v1/reporting-data-expectations).
